# 凭据墙:拿到指纹却卡在"登不进去"

**症状**:目标就在眼前,端口/端点/组件都清楚了,但所有入口都要认证;试了几组口令没中,
再试下去就是无尽的爆破 —— 时间全烧在这一步。

**这张卡解决什么**:把"盲目爆破"换成**有顺序、有节奏、有判据**的凭据作业。
核心认知只有一句:

> **认证服务几乎总有限速,所以"字典有多厚"远不如"顺序有多对"重要。**

实测参考(不同目标数值不同,量法见下):有的目标 SSH `>1 并发即 RESET`、冷却 10~12 秒、
单发认证 2.5~3 秒 ⇒ **有效速率不到 1 发/秒**;有的 FTP 每连接固定 3 秒延迟(tarpit)、并发上限约 40。
一张几千条的字典**永远跑不完**;排在第一百位才出现的正确口令等于没有。

---

## 第 0 步:先判通道,再谈口令

"能 ping 通"不等于"能用"。**判定必须读协议真码**,不要信表层现象:

- `nc -zv host 22` 返回 `succeeded` **可能是假象** —— 实测有的环境控制面直连返回成功,
  真握手却是 `kex_exchange_identification: read: Connection reset by peer`。
  判据是**真跑一次协议交互**(`ssh`/`sshpass` 看 rc 与 stderr、或 `socket` 读 banner)。
- HTTP 层显示 `000`/超时,也要用裸 socket 复核一次 —— 反代/网关会吞掉真实错误。
- **同一台机器不同源 IP 的待遇可能完全不同**(源 IP 过滤):控制面不通、从内网跳板通是常态。
  内网横向题尤其常见,**先把跳板建起来再谈爆破**。

如果目标有多个入口(FTP/SSH/Web 面板/telnet),**先把每个入口的可用性各判一次** ——
有的入口对特定账号是**结构性拒绝**(如 vsftpd 的 `userlist` 让 `admin` 在 `USER` 阶段直接 530),
那种入口**口令面永远不会生效**,不要在上面耗时间,换入口。

## 第 1 步:先量限速窗口,再发字典

**没量过就开投 = 百分之百误判**。`Connection refused`/`EOF`/timeout 里混着"口令错"和"被限速",
分不开就会把真口令当错口令扔掉,还会得出"字典里没有"的错误结论。

量法(串行、小样本):

1. 拿 5~10 条**确定错误**的口令,逐发投,记每发的耗时与返回码。
2. 观察:**单发耗时**(有没有固定 tarpit)、**第几发开始被拒**、**被拒后的冷却时长**。
3. 并发再试 2/4/8,找到**并发上限**(超过就拒的那个点)。
4. 得出**安全速率**(如"串行、每发间隔 ≥3 秒")后才开始正式投递。

## 第 2 步:用户名面差分(免费的一步)

很多服务对**不存在的用户**和**存在的用户**返回不同码 —— 这一步是免费的账号枚举,先做:

- 例:FTP `USER` 阶段 `530 Permission denied`(硬拒)vs `331 Please specify the password`(过);
  SSH 则通常**不区分**(统一 `Permission denied`),别把它当枚举手段。
- 注意反例:vsftpd 对**大量常见名**都回 `331`,`331` 只证明"不在 userlist 硬拒名单里",
  **不等于账号存在**。别把 `331` 当"有效账号"写进结论。
- 枚举出来的有效名按**原顺序**保留,别重排。

## 第 3 步:口令面按顺序组表(顺序即策略)

用 `tools/dict_prep.py` 组表,**分段顺序固定、不允许重排**:

| 段 | 内容 | 为什么排在那个位置 |
|---|---|---|
| ① 厂商定向 | 按指纹取的厂商表(含 `产品词@年份` 形态打头) | 指纹已经告诉你是谁家的产品,这族命中率最高 |
| ② 已观测凭据(复用值) | 本目标其它组件上已经拿到的口令 | 内网跨系统复用是最高频的现实,几乎零成本 |
| ③ 跨轮已观测 | `knowledge/wordlists/observed-passwords.txt`(历史交战中可复用的通用弱口令/默认值) | 别家产品上出现过的默认值常常复用;本表**不含题号/答案**,由 `tools/cred_harvest.py` 过滤入库 |
| ④ 变形族 | `tools/gen_weak_variants.py` 生成 `weak-leet` / `weak-affix` | `P@ssword`/`Admin@123`/`1qaz@WSX` 这类值只在这两张表里,通用高频序覆盖不到,生成成本为零 |
| ⑤ 产品词×年份族 | `tools/gen_product_year.py` 现场生成 | 通用字典**永远**覆盖不到这类形态,而生成成本几乎为零 |
| ⑥ 通用高频序 | `系统与通用弱口令_base` | 兜底 |

```bash
# 拿到指纹(如泛微 OA)之后:
python3 tools/gen_product_year.py --vendor 泛微 --years 2023,2024,2025   # 看一眼年份族
printf '%s\n' "$已拿到的口令" >> observed_creds.txt                      # 记复用值
python3 tools/dict_prep.py --vendor 泛微 --reuse observed_creds.txt --out pw_ordered.txt

# 跨轮积累(合法投机,不是作弊):把你在**别的题/别的轮**见过的通用弱口令收进观察库。
# 过滤规则:拒收 flag、uuid/哈希、题号/任务 ID、只对单个实例有效的临时口令;只收人可读、可复用的弱口令。
python3 tools/cred_harvest.py --file 我的口令笔记.txt     # --dry-run 可先看会收什么
python3 tools/gen_weak_variants.py                        # 需要时重建 weak-leet / weak-affix
```

**为什么必须现场生成"产品词×年份"**:国产 OA/设备有很强的"产品名+年份"口令设计习惯
(`weaver@2023`、`Ecology@2024`、`Huawei@2023` 这类),市场上没有这份组合表,任何现成字典都覆盖不到;
而它只要几行代码就能产。**漏了这一族,就等于把最可能的那几条永远排在字典之外。**

自己手攒的表最容易犯的错:**词对了、形态不全**。比如想到了厂商词却只写 `weaver123`/`ecology`,
漏掉 `Weaver@2023` 这种"首字母大写 + @ + 年份"—— 这一维漏掉就是白跑。
拿 `gen_product_year.py --show-forms` 对一遍形态清单再定稿。

## 第 4 步:按节奏投递,绝不并发打爆

- **串行 + 固定间隔**,速率取第 1 步量出来的安全值。
- **绝不并发轰炸**:实测有目标被本方并发爆破打到 `Error reading SSH protocol banner`/EOF,
  最终**整台文件服务器容器从内网消失**(服务被打挂),剩下所有时间全废 ——
  **把自己要打的通道打烂是最贵的错误**,比打错口令贵得多。
- 多 agent 并行时**先协调**:同一台目标上只允许一个 agent 做凭据投递,
  其余人换面(源码分析、其它端口、其它主机)。谁在做、做到哪,写进黑板。

**单连接多口令(重要提速技巧)**:`sshpass` 一发一连,在"每连接固定延迟"的服务上浪费极大。
改用 ssh 原生的 `SSH_ASKPASS`:问口令时 ssh 会调你的脚本,脚本从队列文件弹一条并重写队列 ——
**一条 SSH 连接内可以连续消耗多条口令**(实测可到 6 条/连接以上),把每连接开销摊薄。
FTP 侧则用一条控制连接连续 `USER`/`PASS`(注意 `MaxLoginAttempts`)。

## 判据与收尾

- **命中判据要写死**,别靠肉眼看输出:成功通常是 `rc=0` / 状态码跳变(302)/ 出现登录后页面特征;
  失败里混着限速错误时,**限速类错误必须重投**(它们不是"这条口令错")。
- 全表跑完仍无命中 ⇒ 结论是"**口令面不在这批候选内**",不是"这条路死了":
  回头补 ③ 段的年份/形态、补 ④ 段、或去找凭据的其他来源(配置泄露、`.bash_history`、
  自建服务的源码、上一跳机器上的备份文件)。
- 拿到一个凭据后**立刻记进 `observed_creds.txt`** 并回填黑板 —— 下一跳先试它。

## 反模式清单(踩过的坑)

- ❌ 没量限速就并发开跑 → 把目标打挂 + 把限速错误当"口令错"
- ❌ 字典只准备了一维(有厂商词、没有 `产品词@年份`) → 最可能的那几条不在表里
- ❌ 在结构性拒绝的入口上死磕(如 FTP 的 `admin` 恒 530) → 该换入口而不是换字典
- ❌ 执行时临时重排字典顺序 → 顺序是策略,重排等于把最好的候选挪到后面
- ❌ 多 agent 同时轰同一个认证服务 → 互相踩踏,全是误报
- ❌ 把"全表跑完没中"当成"没有弱口令" → 大概率是候选面不够,不是目标不弱
