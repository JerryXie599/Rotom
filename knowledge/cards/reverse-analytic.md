# 卡:逆向/二进制类的通用解法(写脚本算,不在 thinking 里手推)

**总则**:凡是"算法还原、密钥/口令推导、状态空间搜索",一律**写 Python 脚本跑**;
单次思考只决定"下一步跑什么脚本、传什么参数"。

| 题型 | 特征 | 最短路径 |
|---|---|---|
| 状态机 + 密钥流 | `.data` 里有一张表 + 某常量异或(如 `0xa5`) | 从反汇编抄状态转移表 → Python 复现 → 逆推输入(逐字节/逐块) |
| 自解密/加壳 | 入口处先 XOR/RC4 解出下一段 | `rabin2 -zz`/`strings` 找线索;**静态还原**优先,必要时在沙箱里 dump 解密后内存 |
| 弱哈希/碰撞 | FNV-1a、CRC、自研混合 | 直接实现逆函数(逐字节确定性,不用搜索) |
| XTEA/RC4/TEA 变体 | 常量特征(`0x9e3779b9` 等) | 识别算法 → 用现成实现解密(注意轮数/字节序/填充) |
| Go 二进制 | 符号多、字符串拼接多 | gdb 断点取函数返回 / 用 `go tool objdump`;别硬读静态大函数 |
| 服务端内存泄露 | TCP 服务返回"多余"字节 | 按协议逐步发请求,观察越界读到的内容;often 直接含 flag |
| 固件/多轮变换 | 文件头魔数 + 多段处理 | 逐层脱(每层做一次 `file`+`binwalk`),写脚本串起来 |

## 纪律
- 用 `pwn64`(Linux)跑 pwntools/angr/radare2;本机 macOS 跑不了 amd64 二进制;
- 每层解开都 `file` 一次确认,并把中间产物存盘(别只在内存里折腾);
- 附件给了 libc 就用附件偏移;不要联网查 libc 版本。
